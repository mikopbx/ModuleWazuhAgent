# ModuleWazuhAgent

Модуль MikoPBX запускает на станции официальный агент Wazuh и отправляет на ваш менеджер Wazuh
состав пакетов станции. По этому составу менеджер находит уязвимые версии.

Статус: тестовая версия 0.1, только x86_64. См. [issue #1](https://github.com/mikopbx/ModuleWazuhAgent/issues/1).

## Как работает

- При установке станция скачивает `wazuh-agent 4.14.9-1` (amd64) с packages.wazuh.com и проверяет
  его SHA-256. Станции нужен доступ к packages.wazuh.com один раз.
- В MikoPBX нет пакетной базы. При каждом запуске модуль записывает `/var/lib/dpkg/status`
  из манифеста образа `/offload/package-manifest.tsv` (MikoPBX 2026.6.80 или новее).
  Для каждого пакета указаны продукт и вендор NVD, поэтому менеджер сопоставляет CVE.
- Работают только `wazuh-agentd` и `wazuh-modulesd` с syscollector. SCA, контроль целостности
  файлов, сбор журналов, active response и удалённые команды выключены.
- Ключ агента хранится в папке базы модуля. Он переживает перезагрузку и обновление модуля.

## Настройки

| Поле | Значение |
|---|---|
| Адрес менеджера | Имя или IP менеджера Wazuh |
| Порт менеджера | Порт событий агента, по умолчанию 1514 (регистрация идёт через 1515) |
| Пароль регистрации | Только если менеджер требует `authd.pass`. После сохранения не показывается |
| Имя агента | Имя на менеджере. Если пусто — имя станции |
| Группы агента | Группы для регистрации через запятую |

Сеть: исходящие TCP 1514 и 1515 к менеджеру. Входящие порты не открываются.

## Ограничения

- Будут ложные срабатывания: сравнение версий не видит патчей MIKO, CVE ядра не отфильтрованы
  по конфигурации сборки.
- Зависимости Composer в инвентарь не входят.
